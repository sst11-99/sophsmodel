## Working flow

`/` → Model Login → Try Example photos. The example uses only five images already approved on the public site, stores choices in a separate browser-only namespace and makes no model/auth/database writes. Agency and model decisions, categories, framing, uses, notes and photo order can differ. Compare shows the actual changed fields; each view keeps the normal photo filters. Original local Sophie records remain untouched. Example photo uploads are intentionally unavailable because it is a demo.

The private portal transport uses Supabase Auth and row-level access on assigned collections. Only the assigned model side or agency side can be edited, even if someone manipulates the interface. Authenticated users with no assignment cannot see model records. Memberships must be provisioned by the agency; a newly created authentication account does not grant collection access. Only the model's own email identity and explicitly assigned agency emails should be added. Database code, private audit trigger and non-public `model-review` storage bucket are applied; no real model account, collection assignment, photo upload or sign-in email has been created in this checkpoint.

Each saved choice has actor user ID, timestamp and revision, plus append-only change history. An existing-row revision conflict stops editing and asks for reload. Agency and model versions never overwrite each other. Multiple agency staff share the agency side through separate memberships. Public example edits use local storage; real model edits use authenticated database writes. Original uploads are retained in private storage; private media is never part of the GitHub or public serving bundle.
